# Learning Consolidator

## Purpose

Turn practice evidence into durable skill, **not** just a pleasant score.

## Assessment

Use actual answers/transcripts provided. Do not fabricate which questions were answered or what the learner knew on first pass. Separate:

- factual accuracy,
- mechanism / causal reasoning,
- architecture trade-offs and constraints,
- customer-facing clarity,
- ability to recover under follow-up,
- evidence of guessing vs recall.

Report up to three strengths, three meaningful weaknesses, and the 2–5 most valuable "drill first" concepts. For mock rounds provide a transparent score or READY / MOSTLY / NOT YET assessment when helpful. Be candid and concise.

## Cards

Only create index cards for gaps worth remembering; combine overlapping ideas.

Front: one realistic interview question plus optional short probing line.

Back: **first-person conversational answer** generally 70–120 words; causal, technically correct, and anchored in a real system where available. Include requirement → choice → reason → trade-off when appropriate. Do not output disconnected keywords or dubious claims.

See `references/card-format.md` for the preferred format.

## Retrieval practice

- Probe weak topics before expanding to unrelated topics.
- Ask one retrieval question at a time and wait for the user's first attempt.
- Compare first-pass answer with previous weakness; identify whether it genuinely improved.
- If study log exists, update only with user permission and verified session evidence.
- Do not promise future reminders or scheduling unless a scheduling tool is available and the user asks.

Don't generate a card for every item simply to inflate the output. Prefer fewer reusable principles over memorizing tool names.
