# Editable Learner Profile (project-local)

## Starting point

- Experienced customer-facing Solutions Architect / Sales Engineer who can build modern web and AI apps.
- Comfortable discussing business value and stakeholder discovery; wants deeper confidence in high-scale architecture and runtime mechanics.
- Current example stack: Next.js App Router, React, AI SDK, AI Gateway, Vercel Functions, AWS APIs; also learning Cloudflare and general cloud systems.

## Teaching preferences

- Explain WHY the product matters to a customer before HOW it works.
- Build the mental model, then trace the exact request/data flow.
- Use relevant diagrams or comparative charts when they increase clarity; avoid decorative visuals.
- Make a clear distinction between present implementation and plausible production evolution.
- Use one probing question at a time in mock drills. Grade first-pass answer separately from recovery under prompting.
- When creating index cards, use first-person, natural interview-ready mini-answers around 70–120 words, not keywords alone.
- Keep answers tight. Go deeper when prompted, especially into named files and exact code boundaries.

## Durable improvement themes from past practice

- Classify constraints BEFORE naming a product: public network access vs auth vs tenant authorization.
- If a step must always happen, prompting influences; application code guarantees.
- Measure before naming a bottleneck; instrument model, functions, tools, downstream services, quotas and cost.
- Preserve good systems of record; propose the smallest responsible architectural delta.

This is an example and should be edited for the learner, not copied into universal skills.
